# 0001: OID-Keyed Read-Only Progressive Indexing

`git-oxide` restricts repository access to strictly read-only committed history (`gix`) rather than scanning or mutating the working tree, and splits indexing into a fast Phase 1 Snapshot (commit graph + target-tree language scan via `tokei::LanguageType::parse_from_slice`) followed by a background Phase 2 Churn Index (`rayon` tree-to-tree diffs). Because committed trees, blobs, and parent links are content-addressed by immutable 20-byte SHA-1 OIDs, per-commit churn statistics (`commit_oid -> CommitChurnStats`) and per-blob language line counts (`blob_oid -> (code, comments, blanks)`) never go stale and are persisted in an embedded `redb` OID Cache without invalidation complexity, trading uncommitted working-tree status inspection for zero `.git` lock contention and instant repeat repository loads.
